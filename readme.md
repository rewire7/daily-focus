# Daily Focus

하루 10~20개 수준의 개인 할 일을 브라우저에서 즉시 기록·분류·추적하는 단일 사용자용 웹 앱입니다.
로그인, 서버, 빌드 과정 없이 `index.html`을 더블클릭하면 바로 실행됩니다.

## 실행 방법

`index.html`을 브라우저(Chrome/Edge/Firefox/Safari 최신 버전)로 열면 바로 사용할 수 있습니다.
별도 설치, 빌드, 서버 실행이 필요 없습니다.

## 기술 스택

HTML5 + CSS3 + Vanilla JavaScript(ES6+)만 사용합니다. 외부 라이브러리·프레임워크·빌드 도구는 없습니다.

```
daily-focus/
├── index.html
├── style.css
├── app.js
└── 할일관리앱_PRD.md
```

## 데이터 저장

- `localStorage`의 `dailyfocus.todos.v1`, `dailyfocus.filters.v1` 키에 저장됩니다.
- 브라우저·기기별로 데이터가 격리됩니다(동기화 없음). 상단 "내보내기/가져오기"로 JSON 백업이 가능합니다.

## 알려진 제약사항 / 개선 여지

이 항목들은 의도적으로 범위에서 제외했거나, 자동화 환경의 한계로 완벽히 실측하지 못한 부분입니다. 실사용 전 참고하세요.

### 기능 범위
- **완료 체크 애니메이션은 짧은 팝(pop) 효과 정도**입니다. 색종이(컨페티) 같은 화려한 연출은 없습니다.
- **저장 실패 안내는 배너 방식**입니다. `localStorage` 저장이 실패(용량 초과, 시크릿 모드 등)하면 화면 상단에 빨간 배너가 뜨고, 다음 저장이 성공하면 자동으로 사라집니다. 다만 배너는 페이지를 벗어나면(새로고침) 사라지므로, 근본 원인(예: 브라우저 저장공간 부족)은 사용자가 직접 해결해야 합니다.
- **다크 모드, 마감일/알림, 반복 일정, 하위 작업, 협업 기능은 PRD상 v1 범위 밖**이라 구현하지 않았습니다.

### 접근성 관련 트레이드오프
- **카테고리 배지·필터 탭은 높이만 44px를 보장**하고 너비는 텍스트 길이에 맞춥니다(체크박스·수정·삭제 버튼은 44×44px 정사각형). 배지/필터를 44px 정사각형으로 강제하면 "업무", "개인" 같은 짧은 라벨이 불필요하게 큰 사각형이 되어 미니멀한 톤과 어긋나기 때문에 의도적으로 다르게 처리했습니다.
- **항목을 체크·수정·삭제한 직후 포커스가 사라집니다.** 목록 전체를 통째로 다시 그리는 아키텍처(부분 DOM 조작 금지) 특성상, 조작한 요소가 매번 새로 생성되기 때문입니다. 키보드로 연속 조작하려면 Tab을 처음부터 다시 눌러야 할 수 있습니다. 모든 조작 자체는 키보드만으로 가능하지만, 연속 조작의 편의성은 완벽하지 않습니다.
- **필터 탭·진행률 텍스트는 동적으로 바뀌는 내용 자체를 접근성 이름으로 사용**하고, 별도 `aria-label`을 붙이지 않았습니다(고정된 `aria-label`을 붙이면 실제 표시 텍스트와 어긋나 더 혼란스럽기 때문입니다).

### 검증 관련
- **320px 뷰포트 테스트는 실제 브라우저 창 크기 조절이 아닌 `<iframe>`을 이용해 검증**했습니다. 이번 자동화 테스트 환경에서는 실제 브라우저 창/뷰포트 크기 조절이 반영되지 않아, 320px 폭의 iframe을 페이지에 삽입해 그 안에서 레이아웃과 미디어 쿼리 동작을 확인했습니다. 실제 모바일 기기·브라우저 반응형 모드에서 다시 한번 확인하는 것을 권장합니다.
- **성능(항목 100개 기준 렌더링 100ms 이내)은 별도로 벤치마크하지 않았습니다.** 항목마다 DOM 요소를 5~6개씩 새로 생성하는 구조라 100개 정도까지는 문제없을 것으로 예상되지만 실측하지는 않았습니다.
- **Chrome 계열 브라우저에서만 테스트했습니다.** Firefox, Safari에서의 동작은 확인하지 않았습니다.
- 색상 대비(WCAG AA 4.5:1)는 수치 계산으로 검증했습니다. 카테고리 배지(업무/개인/공부 배경색 + 어두운 텍스트)는 모두 5.5:1 이상, 본문 보조 텍스트는 7:1 이상입니다.

### 코드량
PRD가 제시한 "전체 코드 500줄 내외" 목표보다 실제 결과물이 훨씬 큽니다(`app.js` 728줄, `style.css` 486줄, `index.html` 82줄, 합계 약 1,300줄). 카테고리·필터·인라인 수정·백업·접근성까지 PRD 전 범위를 충실히 구현하고, CSS도 변수·반응형·hover/focus까지 체계적으로 정리하다 보니 크게 늘었습니다. 기능을 덜어내지 않는 한 더 줄이기는 어렵습니다.

## 다음에 이어서 하면 좋을 것

- 조작 후 포커스를 다음 논리적 요소(예: 삭제 후 다음 항목 체크박스)로 옮겨주는 포커스 관리
- `localStorage` 실패 시 배너뿐 아니라, 실패가 반복될 경우 내보내기를 권유하는 안내 추가
- 실제 모바일 기기에서의 반응형·터치 동작 재검증
- 100개 이상 항목에서의 실측 성능 테스트
